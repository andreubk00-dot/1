# OSTATOK 1.22.0-dev9 — Release Candidate / Balance & Stability

База: `1.22.0-dev8 Faction Endgame / Strategic Chains`.

Этот этап не добавляет новый крупный контентный слой. Цель dev9 — стабилизировать всю ветку 1.22 перед `1.22.0 Stable`: долгий прогон экономики, закрытие эксплойтов, проверка старых сохранений и полный regression.

## 1. Долгосрочная устойчивость поселений

До dev9 обычный ежедневный расход ресурсов был строго отрицательным. Если несколько десятков игровых дней полностью игнорировать поселения, неосновные ресурсы математически стекали в ноль и могли надолго зафиксировать мир в глубоком кризисе.

Добавлено слабое аварийное самообеспечение поселений:

- начинает работать только ниже `35` единиц ресурса;
- сила восстановления пропорциональна глубине провала;
- не способно вывести поселение в здоровое состояние;
- стабилизирует запущенный ресурс внутри кризиса/дефицита, а не отменяет необходимость торговли, контрактов и маршрутов;
- профильное снабжение, спасённые рейсы, открытые маршруты и endgame-инфраструктура по-прежнему дают значительно больший эффект.

В 180-дневном unattended soak ни один ресурс не падает в математический ноль, но поселения без игрока остаются в состоянии дефицита.

## 2. Закрыт buy → sell ресурсный эксплойт

Раньше продажа товара поселению увеличивала его абстрактный ресурс, а покупка того же товара ресурс не уменьшала. Поэтому можно было купить предмет у того же торговца и продать обратно: игрок терял талоны, но поселение получало ресурс «из воздуха».

Теперь:

- покупка конечного товара у поселения немного уменьшает соответствующий абстрактный ресурс;
- продажа товара увеличивает его на ту же единицу;
- обычный buy → sell roundtrip больше не создаёт еду/медицину/технику/безопасность;
- межпоселенческая торговля по-прежнему полезна: вывезенный из одного рынка товар можно реально привезти в нуждающийся другой.

## 3. Сделки теперь проверяются экономикой повторно

`TradingMarket` больше не доверяет переданной UI сумме вслепую.

Перед мутацией состояния повторно проверяются:

- количество;
- актуальный stock;
- репутационный доступ;
- текущая цена;
- запас талонов игрока/торговца;
- barter delta;
- запрет same-item barter на уровне economy API.

Подменённая/устаревшая сумма покупки, продажи или бартера отклоняется без мутации экономики.

## 4. Long-run balance soak

Новый `tests/test_release_candidate_balance_122.gd` проверяет:

- 180 игровых дней без помощи поселениям;
- 180 дней с немедленным спасением каждого supply incident;
- 365 дней с полностью завершённой endgame-инфраструктурой и открытыми маршрутами;
- resource bounds `0..100`;
- отсутствие пассивного начисления талонов;
- полезность спасения профильных рейсов без автоматического решения остальных дефицитов;
- ограничение истории supply-events;
- buy/sell spread на всех восьми торговцах;
- sweep по репутации `-100..250`;
- sweep по ресурсам от полного кризиса до `100`;
- защиту от подмены transaction totals;
- отсутствие ресурсной инфляции от локального buy/sell roundtrip.

Результат: `7891 checks, 0 failures`.

## 5. Save migration

Новый `tests/test_release_candidate_save_migration_122.gd` запускает production `Main` на сохранении старого формата без полей dev5/dev6/dev8.

Проверено:

- старый `world_day` сохраняется;
- талоны, репутация и ресурсы не меняются;
- автоматически создаются `relations`, `world_influence`, `supply_events`, `faction_endgame`;
- старому сохранению не выдаётся бесплатный endgame progress;
- первый supply incident после миграции планируется через 3–6 дней от текущего дня, а не возникает немедленно из-за старой даты;
- повторное сохранение/загрузка мигрированного состояния работает production-путём.

Результат: `15 checks, 0 failures`.
