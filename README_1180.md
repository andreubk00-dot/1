# OSTATOK 1.18.0-dev6 — Arsenal Expansion II

Текущая рабочая ветка после 1.17.2 Long-Term Gear Progression. Это development/QA
candidate, а не подтверждённый stable-релиз.

## Арсенал этапа

- **ППС-43** — автоматический ПП под 7.62×25: высокий темп, 35 патронов, короткая
  эффективная дистанция и заметный разброс.
- **ИЖ-81** — помповый 12 калибр: shell-by-shell reload, более собранная осыпь,
  медленнее базового дробовика.
- **АКС-74У** — компактный автоматический карабин под новый 5.45×39: легче АКМ,
  быстрее и мобильнее, но хуже по дальности/стабильности.
- **Винтовка Мосина** — 7.62×54R: 5 патронов, поштучная зарядка, высокий урон,
  дальность и шум, низкий темп.
- Новые боеприпасы: **5.45×39** и **7.62×54R**.

Для всех четырёх новых стволов уже есть отдельные weapon-model rows, inventory art,
ground/world art, HUD art и полный набор из 21 animation clip. Они используют обычную
instance-id систему, поэтому одинаковые экземпляры не делят магазин, износ или модули.

## dev2 — настоящий audible weapon layer

В dev1 существовала только числовая «громкость» для слуха заражённых. В dev2 добавлен
реальный слышимый слой:

- отдельный оригинальный WAV-выстрел для каждого из 10 канонических стволов;
- отдельный приглушённый WAV для ПМ с установленным глушителем;
- пять механических reload-профилей: pistol, SMG, rifle, shell и bolt;
- shell-by-shell оружие проигрывает механику на каждом цикле заряжания;
- пул из шести AudioStreamPlayer не обрезает хвост предыдущего выстрела при очереди;
- громкость аудио и gameplay noise для AI остаются разными параметрами;
- пустой магазин даёт тихий dry-fire click, но не создаёт AI gunshot event;
- `tools/build_weapon_audio.py` детерминированно пересобирает весь временный набор.

Это рабочие development-ассеты. Финальный художественный audio/atmosphere pass по-прежнему
остаётся на 1.29, но оружие 1.18 больше не является немым placeholder.


## dev3 — полноценный combat loadout

Расширение арсенала теперь не ограничено инвентарём. Старый quickbar был жёстко прошит под
ПМ / дробовик / АКМ и три melee-предмета, поэтому новые стволы нельзя было сделать частью
обычного боевого набора. В dev3 это исправлено:

- все 6 быстрых слотов принимают любой зарегистрированный firearm или melee;
- в открытом инвентаре нужно выбрать оружие и нажать `1–6`, чтобы назначить его в слот;
- если предмет уже назначен в другой слот, привязки меняются местами, без дублей;
- закрытый инвентарь возвращает `1–6` к обычному мгновенному переключению;
- binding сохраняется в сейве; схема поднята до `save_version = 101`;
- старые сейвы без quickbar-данных получают прежний безопасный набор по умолчанию;
- HUD-иконки имеют отдельные layout-профили для всех 10 firearms, включая новые четыре;
- подсказка управления касается только интерфейса и не раскрывает источники добычи.

Добавлен `tests/test_quickbar_loadout.gd`. На этапе dev3 regression-набор содержал **35 suites**.

Дополнительно усилен статический visual contract Arsenal Expansion II: grip/front-hand,
reload и muzzle points новых стволов проверяются на попадание внутрь source frame, а muzzle
обязан оставаться впереди обеих рук. Это не заменяет живой rendered QA, но ловит грубые
ошибки посадки до запуска движка.

## dev4 — distinct in-hands art + combat-role lock

Проверка dev3 обнаружила блокирующую ошибку asset pipeline: новые `animation prefix` существовали,
но ППС-43, АКС-74У и Мосин фактически использовали одинаковую АКМ-геометрию персонажа, а ИЖ-81
копировал старый shotgun silhouette. Это исправлено на уровне генератора, а не ручной подменой PNG:

- `tools/survivor3d.py` теперь содержит отдельную in-hands геометрию ППС-43, ИЖ-81, АКС-74У и Мосина;
- все **84** новых baked animation sheets перебиты из этих четырёх разных геометрий;
- ни один из 84 листов больше не является byte-identical clone старого АКМ/дробовика;
- static QA проверяет размеры каждого листа, непустые frame cells и безопасный отступ от границ кадра;
- representative `Idle / Attack1 / Taunt / Run` дополнительно обязаны различаться между четырьмя новыми стволами;
- добавлен параллельный baker `tools/build_survivor_parallel.py`;
- `QA_1180/static_inhands_contact.png` даёт быстрый pre-engine contact sheet по четырём направлениям.

Добавлен `tests/test_arsenal_combat_roles.gd`: фиксируются body-shot breakpoints против normal/runner/brute,
DPS-band автоматического оружия, лестница дальности/разброса/шума и вес боеприпасов. Это не заменяет
живую стрельбу, но не позволяет случайным числовым правкам превратить новые роли в клоны или strict upgrade.

## dev5 — manual action cycle / pump + bolt

Закрыт ещё один gameplay/animation placeholder. До dev5 помповые ружья и Мосин после
выстрела просто ждали `fire_cooldown`: механика помпы/затвора визуально и звуково не
происходила. Теперь это отдельный post-shot action:

- базовый помповый дробовик и **ИЖ-81** имеют `action_cycle = pump`;
- **Мосин** имеет `action_cycle = bolt`;
- после recoil выдерживается короткая задержка, затем запускается отдельная `Attack2`-фаза;
- `Attack2` для shotgun/ИЖ-81 показывает ход цевья назад/вперёд, для Мосина — работу затвора;
- добавлены отдельные `pump_cycle.wav` и `bolt_cycle.wav`;
- reload не накладывается на незавершённый ручной цикл;
- switch/death/load корректно сбрасывают transient cycle-state;
- `tools/build_weapon_audio.py` теперь детерминированно пересобирает **19 WAV**, включая cycle FX;
- visual QA runner получил `--qa-cycle` и отдельные кадры shotgun / ИЖ-81 / Mosin;
- engine runner теперь сначала запускает runtime SELFTEST через `--qa-selftest-exit`, затем все `test_*.gd`;
- SELFTEST возвращает реальный process exit code, поэтому один runner даёт машинно-проверяемый PASS/FAIL;
- добавлен `tests/test_weapon_action_cycles.gd`. Regression-набор теперь содержит **37 suites**.

Цикл завершён раньше следующего разрешённого выстрела и не добавляет отдельной кнопки:
персонаж выполняет необходимое действие автоматически, как часть поведения оружия.

## dev6 — SELFTEST error-3 fix / inventory-art contract

Пользовательский запуск dev5 показал `ОШИБКИ ТЕСТА: 3`. Разбор встроенного SELFTEST
выявил ровно три причины:

- проверка каталога всё ещё ожидала 46 non-melee inventory icons, хотя после 1.18 их стало **52**;
- exact inventory-art АКС-74У имел ширину 82 px и не помещался 1:1 в его 3×1 footprint;
- exact inventory-art Мосина имел ширину 116 px и не помещался 1:1 в его 4×1 footprint.

В dev6 старый count исправлен, а АКС-74У/Мосин пересобраны соответственно до **74×18**
и **104×18 px**, без увеличения самих предметов и без runtime scaling. АКС остаётся компактным
3×1, Мосин — 4×1.

Добавлен `tests/test_inventory_art_contract.gd`: каждый предмет обязан иметь точную inventory-модель,
а каждый `inventory_icon_regions` region обязан физически помещаться в authored grid footprint при
нативном масштабе. Тот же контракт добавлен в `QA_1180/static_check.py`. Regression-набор теперь
содержит **38 suites**.

Диагностика SELFTEST также изменена: при ошибке HUD показывает первые конкретные причины, а не
только число `ОШИБКИ ТЕСТА: N`. Это не скрывает ошибку и не отключает тест — наоборот, делает
следующую runtime-регрессию сразу диагностируемой.

## QA и интерфейс

- Оружейник использует ScrollContainer и помещает 10 стволов.
- Quickbar — сохраняемый 6-слотовый loadout для любого firearm/melee, а не фиксированный список старого оружия.
- `ТЕСТ: ВСЕ ПРЕДМЕТЫ` строится из `item_defs` автоматически.
- QA-сетка увеличена **14×8 → 16×8**; обычные контейнеры всё ещё 8×8.
- Добавлен `tests/test_arsenal_expansion_ii.gd` и отдельный
  `tests/test_weapon_audio.gd`, `tests/test_arsenal_combat_roles.gd` и `tests/test_weapon_action_cycles.gd`; теперь в проекте **38 test-suite**.
- Каждый канонический firearm обязан иметь отдельный shot WAV и допустимый reload profile.

## Что ещё обязательно проверить/доделать до закрытия 1.18

1. Полный engine regression и SELFTEST на Godot 4.7.2.
2. Rendered visual QA в движке: движение/reload/clipping после dev4 rebake.
3. Живое подтверждение уже зафиксированных combat breakpoints: scatter, cadence, stopping response и фактическая удобность дистанций.
4. Проверка воспринимаемой громкости новых WAV в реальном миксе; финальная запись/дизайн звука всё равно выполняется в 1.29.

## Discovery-first

Внутренние loot tables существуют, но UI не раскрывает источник предмета, шанс выпадения,
cooldown target farming или «правильный» маршрут. Игрок узнаёт закономерности сам через
исследование, риск, повторные походы и собственные заметки.
